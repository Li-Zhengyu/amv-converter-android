# AMV 转换器 v1.3

> 把手机里的视频 / GIF / 图片 / 音乐转换成本地播放器能播的 **AMV** 格式 —— 并且能**在手机里直接播放它**。

**下载**：[`AMV-Converter-1.3.apk`](../../releases) · 170 KB · Android 5.0+ · 无任何第三方依赖

---

> **如果你装过 v1.1 / v1.2**：请升级到 v1.3。
>
> - **v1.2** 修复了**预览与内置播放器画面上下颠倒** —— AMV 格式规定画面"倒着存"、由解码端翻回来，
>   而重构裸帧用的系统 JPEG 解码器不知道这个约定。**转换出来的文件一直是对的**，
>   倒的只是 App 内显示的预览画面。
> - **v1.3** 修复了**切到小窗/分屏后转换任务丢失**，并让**批量选择**变得可发现。

## 这个版本解决了什么

v1.0 能转出正确的 AMV，但有三件事不到位：**慢**、**没有播放器**（AMV 在安卓上根本放不了）、
**界面是系统默认控件堆的**。v1.1 ~ v1.3 把这些一件件做完了。

## v1.3 新增

### 🪟 转换搬到前台服务：小窗/分屏不再丢任务
此前转换跑在界面自己的线程上，界面一被销毁（**切小窗、分屏、被系统回收**）工作就没了。
现在转换在**前台服务**里跑，带进度通知和「停止」按钮；界面只负责显示。

- **切到小窗/分屏、退到后台、息屏，转换都继续**
- 回到 App 时自动接上正在跑的任务，进度照常显示
- 顺手补齐了 `configChanges`（含 `smallestScreenSize`、`screenLayout`），进入小窗/分屏不再重建界面

### 💡 批量选择更容易被发现
系统文件选择器默认单选、**长按**才进多选，几乎没人能自己发现。现在：

- 首次打开选择器会弹一次**操作说明**
- 选文件卡片下方有**常驻提示**，点它可随时再看说明
- 多选后明确提示"已选 N 个文件，进入批量模式"

## v1.2 / v1.1 新增

### 🎬 内置 AMV 播放器
安卓系统**完全不支持** AMV，所以转换完只能拷到播放器里才知道效果。现在：

- 转换完点「**播放效果**」直接看；也可以「**播放 AMV**」打开手机里已有的文件
- 支持 **播放 / 暂停 / 上一帧 / 下一帧 / 拖动进度条定位**
- **系统"打开方式"**：在文件管理器或微信/QQ 分享里点 `.amv`，可以直接选本 App 打开
  （已注册 `video/x-amv`、`application/octet-stream` 与 `.amv` 路径模式）

播放器是纯 Java 实现的：解析 AMV 容器 → 把裸帧重建成标准 JPEG 交给系统解码器 →
音频走 IMA ADPCM 解码 + AudioTrack。**解码结果与 FFmpeg 位级一致**（445,410 个样本 0 差异）。

### 📚 批量转换
一次多选文件自动进入批量模式：清单式逐条显示状态（等待 / 百分比 / 完成体积 / 失败），
总进度条 + "第 N/M 个"，结束后汇总成功数、失败数、总体积，失败原因逐条列出。转换期间屏幕常亮。

### ⚡ 速度优化
之前的实现**每一帧都要从解码器拷贝出来**——哪怕这帧根本用不上。对于一个 2336×1080 的源，
一帧就是 3.8 MB 的无用拷贝。现在：

- **只拷贝用得到的帧**：帧选择下沉到解码器，用不上的直接从缓冲区丢弃。
  30fps→15fps 省一半拷贝，60fps→10fps 省约 83%
- **色度批量拷贝**：半平面（NV12/NV21）色度从"每像素一次 `ByteBuffer.get`"
  （1080p 每帧上百万次调用）改为整行批量读取 + 本地解交织
- **缩放权重表跨帧缓存**：此前每帧重建约 350 个权重数组
- **分段耗时显示**：转换结束显示总耗时、处理帧率、解码耗时、取帧拷贝耗时、
  其余（缩放编码等）与**所用解码器名** —— 慢在哪一眼可见。若"解码"占大头说明手机在软解；
  若"其余"占大头则降低分辨率/帧率最有效

### 🎨 界面重做
- 设置项从下拉框改为 **chip 选择器**：一屏可见、一次点击，
  也解决了窄列里"160x120 经典"被挤成三行的排版问题
- 卡片式布局、渐变标题栏、圆角主按钮；播放器为深色界面
- 进度卡片增加输出画面实时预览与耗时明细

### ✅ 推荐参数组合
把**实测可播放**的配置设为默认：**160x128 · 10 帧/秒 · 拉伸**
（高度 128 是 16 的倍数、10 整除 22050，落在格式的安全角落里），界面上会有"已实测可播放"标注。

## 修复

| 问题 | 影响 |
|---|---|
| **切小窗/分屏后任务丢失**（v1.3 修复） | 转换改由前台服务执行；界面可被销毁重建，任务与进度都在 |
| **批量选择不易发现**（v1.3 修复） | 首次打开选择器弹说明 + 常驻提示 + 多选后确认提示 |
| **预览/播放器画面上下颠倒**（v1.2 修复） | AMV 画面按格式规定倒着存、解码端负责翻回来；渲染前少了一次垂直翻转。实测：重建帧与源帧正立对比 5.6 dB、与上下翻转对比 **45.4 dB**（只翻垂直就到 45.4 dB，也证明没有左右翻转）。**文件本身一直正确** |
| **重建 JPEG 的 DHT 段长度字段少 2 字节** | 任何标准解码器都无法解码 → **转换中的输出画面预览和播放器一直是黑屏** |
| **帧源重构后残留双缓冲交换** | 首帧空白 + 整段视频**滞后一帧**（由端到端回归发现：PSNR 24.6 → 17.7 dB） |
| **保存失败时吞掉了真实异常** | 只显示"自动保存失败"，无法排查。现在**依次尝试 4 个位置**（`影片/AMV` → `Download/AMV` → 公共 `Movies/AMV` → App 私有目录）并**如实报告落点与失败原因** |
| 保持待用帧时漏调 `releaseOutputBuffer` | 可能耗尽解码器缓冲区 |
| 解码器不上报流结束时的两处死循环风险 | 极端文件下可能卡住 |

## 兼容性

- **minSdk 21 / targetSdk 33**，Android 5.0 及以上
- 体积 **170 KB**，32/64 位均可（纯 Java，无 `.so`）
- **不需要任何权限**（安卓 10+）：选文件用系统选择器，保存走 MediaStore
- 从 v1.0 升级可直接覆盖安装（签名相同）

## 验证

- 与一条**在真实播放器上验证可用**的 FFmpeg 命令对拍（160x128 / 10fps / block_size 2205）：
  容器结构逐字节一致，音频首块 `predictor/step_index/frame_size` 完全相同
- 音频解码与 FFmpeg **位级一致**（445,410 样本 0 差异）
- 画质**优于 FFmpeg 自产的 AMV**：垂直渐变 45.0 vs 36.3 dB，动态图案 24.6 vs 18.2 dB
- 8/8 桌面单元测试通过；ffmpeg 解码本工具产物零错误

**仍未验证**：Android 层未在真机/模拟器上运行过（开发机无设备且无虚拟化权限），
只做了编译期与静态校验。App 内置启动自检（logcat 标签 `AmvSelfTest`），
转换结束会输出分段耗时与解码器名，便于排查。

## 已知限制

- 输入格式取决于**设备解码器**：设备不支持的编码无法转换（不打包软解库的代价）
- AMV 画质由播放器固件固定，只能靠分辨率/帧率控制体积
- 手机本身播不了 AMV 是格式事实 —— 这也是内置播放器必需的原因
